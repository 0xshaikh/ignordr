ignordr

A local, offline debugger and auditor for .gitignore. It explains why git decided the way it did — because last match wins, directories get pruned, and tracked files ignore you entirely.

no dependencies no network read-only by default Python 3.9+

Start

$pip install ignordr
$ignordr explain logs/important.log

Start with explain. It names the exact file and line that decided a path's fate, and tells you precisely why a rule you wrote did not work.

Why .gitignore is hard

Every one of these is true, and all of them bite people:

*.log matches everywhere At every depth: a.log, src/a.log, a/b/c/a.log. /app.log matches only the root.
Last match wins *.log then !x.log keeps it. Reverse the order and it's gone. Not first-match, not most-specific — last.
Pruned directories are sealed build then !build/keep.log does nothing. git never descends into a directory it excluded as a directory.
Tracked files ignore you A committed file is not ignored no matter what you write. A fresh clone or git clean -fdx will behave differently from your tree.
** is picky Crosses / only as a standalone component. a/**/z crosses; a**z behaves like a*z.
git stays quiet git check-ignore -v shows one rule for one path. It never explains the other eleven rules you actually care about.

Try it — playground

Edit the rules, edit the paths, and see the decision trail for each one. This runs the same last-match-wins logic ignordr uses, in your browser.

Commands

CommandWhat it does
explain PATH...Trace a path through every rule; report the deciding file and line, and why
auditFull audit: pattern problems plus tracked files an ignore rule matches
lintStatically check patterns only — no file scan, fast, CI-safe
trackedList tracked files an ignore rule would now exclude
scanWalk the tree, mark every file ignored / not, name the rule
check PATH...One-line yes/no; exit-code driven for scripts
fixPropose a deduplicated rewrite as a diff; --apply to write

--json on every command for machine output. Exit codes: 0 clean, 1 findings, 2 usage error.

Examples

The rule that won

$ ignordr explain important.log
important.log  ->  NOT IGNORED  (file)

  decided re-included by !important.log
  at .gitignore:7

        - NEGATION - carves an exception out of an earlier exclusion
        - UNANCHORED - matches by basename at ANY depth below the tree

Why your exception is dead

$ ignordr explain logs/important.log
logs/important.log  ->  IGNORED  (file)

  decided excluded by logs/*.log
  at .gitignore:8

  Pattern evaluation order (last match wins):
      no  'build'                   scope (repo root)
      match  '*.log'                scope (repo root)
      match  '!important.log'       scope (repo root)
      match  'logs/*.log'           scope (repo root)

  WHY IT IS STUCK: your exception '!important.log' in .gitignore:7
  matched, but it is overridden by a later rule.
  '  'logs/*.log' in .gitignore:8 comes after
   ' it, and git gives the LAST matching pattern the decision.
   ' Your exception is dead.

  FIX: move the negation below the exclusion it should override:
        *.log
        logs/*.log
        !important.log

!important.log did match. The failure is pure ordering, and git has no way to tell you that.

Audit a repository

$ ignordr audit
  0 error, 4 warning, 1 info, 9 untracked file(s) ignored

[BROAD_RULE]      broad rule '*.tmp' matches by basename at every depth  @.gitignore:9
                 -> anchor it (e.g. /*.tmp or a/**) if you only meant the root
[TRACKED_IGNORED] tracked file matches an ignore rule; git keeps it anyway (a.log)
                 -> run: git rm --cached a.log
[DUPLICATE]       duplicate rule 'build' also appears in .gitignore:2  @.gitignore:12
                 -> delete the earlier copy (line 2 of .gitignore)

Finding codes

CodeSeverityMeaning
DUPLICATEwarningSame pattern twice in one file; the earlier copy is dead
DEAD_NEGATIONwarningA negation cannot override the exclusion it answers
BROAD_RULEwarningAn unanchored basename rule matches at every depth
SELF_EXCLUDEwarningA rule matches its own ignore file's directory

Semantics model

The engine re-implements git's documented behaviour rather than shelling out to git, so it runs offline and can emit diagnostics git cannot.

ConstructBehaviour
leading /Anchors to the declaring file's directory; not part of the match
/ anywhere elseAnchors too
trailing /Does not anchor; restricts to directories
leading **Un-anchors the whole pattern: **/a/b ≈ a/b at any depth
** mid-patternCrosses / only as a standalone component
*, ?Never cross / (FNM_PATHNAME)
[!abc]POSIX class negation
\!, \#Literal ! / #, not a comment or negation
[abc, trailing \Malformed — never matches
precedenceFile depth, then line number. Last match wins.
pruningA directory excluded as a directory is never descended into; nested negations are unreachable

The differential tests build real repositories, run the real git check-ignore, and compare verdicts. They are the correctness proof.
